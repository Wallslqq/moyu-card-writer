# 墨月写卡器 · DSH 版

**在 DSH 里用聊天的方式，做一张 SillyTavern 角色卡。**

你不用记命令，也不用看懂代码。你只要说"我想做一个什么样的角色"，它会：

调出该用的写卡方法 → 一步一步跟你确认 → 写出成品 → **自己先检查一遍** → 拿给你看 → **你点头了才写进作品**。

> 这是**三明月**的《墨月写卡器》在 DSH 上的移植版。原版是一个网页应用；这个版本保留了它的全部创作知识、挑选知识的规则和检查成品的规则，只换了运行方式。
> 许可：**GPL-3.0-only**。原作者署名与完整改动清单见 `署名与来源.md`。

---

## 一、它和"直接让 AI 写卡"有什么不一样

三件事，缺了任何一件，AI 写卡都会变成"看起来很专业但没法用"：

1. **它用的是整理过的写卡知识，不是模型的通用常识。**
   仓库里 `墨月_harness\知识库\` 有 74 条知识，每条都是针对一个具体环节写的（人物性情怎么写、小型世界观和中型的区别、MVU 开局值的格式……）。你说话的时候，它只挑当前这一步该用的那一条塞给模型——不会把 74 条一起灌进去。

2. **成品是被"程序"检查的，不是被模型自己夸的。**
   模型说"我检查过了"没有意义。这里的检查是一个独立的小程序（`墨月_harness\工具\check.mjs`）：它真的去解析你那份 YAML、真的去数 EJS 标签有没有配对、真的去核对世界书配置有没有写错。**不通过就不许进下一步**，模型不能自己改判。

3. **你不点头，它一个字都改不了。**
   每次写出成品，它会先放进一个"待确认区"，然后停下来问你。你确认之前，你的作品文件丝毫未变。它也不会"顺手帮你优化一下"别的地方——维修时只改被点名的那些问题。

## 二、它能帮你做什么

一张完整的角色卡分成几个部分，它每一部分都能陪你从零做起：

| 部分 | 它做什么 |
|---|---|
| **人物** | 六个栏目：基础信息、生活结构、人物性情、场景表现、衣着风格、备注 |
| **世界书** | 判断你的世界该做小型、中型还是大型，然后按对应规格写条目 |
| **创作规则** | 规定"你"该怎么扮演的那套纯提示词 |
| **开场白** | 首条消息与备用开场，含文风约定 |
| **MVU 变量** | 变量结构脚本、开局值、变量更新规则，以及交叉检查 |
| **状态栏** | 从大白话需求 → 技术路线 → 完整 HTML |
| **消息前端** | 楼层内的自定义界面 |
| **EJS** | 世界书里的条件逻辑工件 |
| **原卡资料** | 导入一张已有的卡，改它的字段、正则、脚本 |
| **检查与导出** | 整份结构检查，导出可导入酒馆的 JSON / PNG |

另外：**作品和对话都存在你自己的电脑上**（`墨月_harness\状态\`），不经过任何服务器。

## 三、你需要准备什么

1. 一台电脑（Windows 最省事；macOS / Linux 命令一样）。
2. **Node.js**。推荐 **24**（作者的开发与验证环境是 24.16）。
   仓库里保留了 13 个 `.ts` 原文件，需要 Node 的类型擦除能力才能加载。**低于 22.18 的版本没有实测过**，如果你看到 `Unknown file extension ".ts"` 这类报错，就是版本太低，装新的即可。
   检查方法：打开命令行，输入 `node --version`。
   没有 Node 的话去 <https://nodejs.org> 下载安装（选 LTS 版就行）。
3. **DSH**（这个项目运行在它上面）。装法见下面第 3 步。
4. **一个能用的模型**。DSH 第一次启动会带你配置。模型要联网，费用由你的服务商决定。

## 四、三步装好

### 第 1 步：把两个文件夹放进去

这个仓库里有两个文件夹是要用的：

```
墨月_harness\      ← 工具、知识库、流程、验收
.agents\           ← 让助手认识"墨月"这个指令
```

把**这两个文件夹整个复制**到你的**工作区根目录**。

> "工作区根目录"是什么？就是你会用 DSH 打开的那个文件夹。新建一个空文件夹专门放卡片最省心，比如 `D:\我的卡片`。

复制完应该长这样：

```
D:\我的卡片\
├─ .agents\
│  └─ skills\moyu-card-writer\SKILL.md
└─ 墨月_harness\
   ├─ 工具\
   ├─ 知识库\
   └─ ...
```

> 如果你的文件夹里已经有一个 `.agents`，直接把里面的 `skills` 合进去就行，不用覆盖。

### 第 2 步：装依赖

打开命令行（Windows：按 `Win` 键 → 输入 `cmd` → 回车），然后：

```
cd /d D:\我的卡片\墨月_harness\工具
npm ci
```

等它跑完（需要联网，几十秒到几分钟）。看到没有红色报错就算成功。

> 如果你拿到的是作者打好的压缩包、里面**已经带了 `node_modules` 文件夹**，这一步可以跳过。
> 如果 `npm ci` 因为网络失败，试试先执行 `npm config set registry https://registry.npmmirror.com` 再重来。

### 第 3 步：启动

```
cd /d D:\我的卡片
npx -y @deepseek-ai/dsh@latest web
```

第一次运行会下载 DSH（要等一会儿）。之后它会给你一个本地网址，用浏览器打开，就进界面了。

## 五、开始用

在界面里新建一个会话，然后跟它说：

```
用墨月帮我做一张角色卡
```

也可以直接敲斜杠命令 **`/moyu-card-writer`**（如果斜杠列表里没看到它，就用上面那句话）。

就这一句。它会：

1. 建好这个作品的"工程文件"；
2. 告诉你现在缺什么、建议从哪一步开始；
3. 到了人物那一步，问你一个具体问题（比如"这个角色大概是个什么样的人？"）。

你正常回答就行——**一次只问一个问题**，不会甩给你一张二十栏的表格。

### 一轮完整的过程

> 下面这段是**示意**（为了让你看懂一轮的形状），不是真实运行记录；实际措辞会不一样。

```
你：她是个在北欧读研的中国女生，家里有钱但不太爱提。

墨月：先记下几个不会变的点……我建议这样处理她的"人物性情"这个栏目。
      （写完 → 自己检查 → 拿给你看）

      【待确认】人物性情 · 周梦瑶
      内核：想要被看见，但不肯先开口。
      ……（完整内容）
      确认写入？（是 / 我再改改）

你：是

墨月：已写入。她的六栏目还差"场景表现""衣着风格""备注"，要继续吗？
```

**"确认写入"这一步是硬要求**，它不会替你点。

## 六、出成品时到底发生了什么（重要）

每次它要"出片"，都会走这四步，顺序不会变：

| 步 | 谁做 | 做什么 |
|---|---|---|
| 1 | 助手 | 按当前专项写出**完整**成品 |
| 2 | **程序** | 独立检查：格式、结构、语法、字段、前后是否一致。有错就打回 |
| 3 | 助手 | 停下来问你：这份要不要写入 |
| 4 | **程序** | 你点头后才真正写进作品文件 |

所以：

- 你觉得不对，直接说"不行，改成……"，它重写。作品文件不动。
- 它在检查里没通过，会自己修；修完再给你看。**不会拿一份没通过的成品糊弄你。**
- 它**不会**偷偷改你没让它改的地方。

## 七、它做不到什么（提前说清楚）

- **没有在真正的酒馆里跑过验收。** 所有检查都是本地的静态检查：它能保证"这份 HTML 语法正确、字段路径对得上"，**不能保证"它在你酒馆里显示出来就是那样"**。最后一步一定要你自己在酒馆里试。
- **没有网页版那种三栏界面。** 原版是左中右三栏 + 页签；这里是命令行助手，所以它用一段文字汇总告诉你"现在在哪、还差什么"。
- **不管上下文压缩。** 那是 DSH 的职责，它不重复造一套。
- **附件和图片没有大小限制**，也不会把图片转成文字塞进对话——图片以文件路径交付，需要时由助手自己去读。
- **没做 NSFW 相关内容。**

## 九、常见问题

**Q：它会不会把我写好的内容覆盖掉？**
不会。规则是"你没有明确要求改的内容一律保留"；而且写入前必须你确认。想彻底安全，先把 `墨月_harness\状态\` 复制一份备份。

**Q：我的卡做完了，怎么拿到手？**
跟它说"导出角色卡"。它会生成：
- 一个 `.json`（大部分工具都能导入）
- 一个 `.png`（角色卡内嵌数据，酒馆里直接当角色卡导入最方便；需要你提供一张封面图）

**Q：作品文件在哪？我能直接看吗？**
`墨月_harness\状态\作品\<卡名>.json`。**能看，但别手改**——手改容易把记录写残，之后检查会报错。要改内容就跟助手说。

**Q：说"校验没通过"怎么办？**
正常。让它按打回的原因修就行，它会拿到一份逐条写明"错在哪、为什么、怎么改"的清单。你不用管细节。

**Q：我觉得它做的决定不对怎么办？**
直接说。路由改哪条专项、检查放宽还是收紧，都写在 `墨月_harness\工具\lib\` 里，改完有自测可以跑。这一块偏技术，建议先跟助手确认。

**Q：能同时做多张卡吗？**
能。每张卡是 `状态\作品\` 下的一个文件，互不干扰。跟它说"换到 XX 这张卡"就行。

**Q：它会不会把我的内容传到网上？**
不会。作品和对话只存在你电脑上。唯一联网的是你自己的模型服务（你在 DSH 里配的那个）。

## 十二、想移植到别的 agent（Codex / Claude Code）的人看这里

**先给结论：只有三样东西是 DSH 专属的——① skill 放哪个目录、② 子代理怎么派、③ 命令行怎么写。
`墨月_harness\` 下面的知识库、工具、流程，一行都不用改**（它们只是普通 Node 程序和 Markdown）。

### 12.1 skill 放哪（最省事的一步）

| 运行时 | skill 目录 | 改动量 |
|---|---|---|
| DSH（本仓库现状） | `.agents/skills/moyu-card-writer/SKILL.md` | — |
| **Codex** | **同一个路径** `.agents/skills/moyu-card-writer/SKILL.md` | **原样可用，不用改** |
| **Claude Code** | `.claude/skills/moyu-card-writer/SKILL.md` | 把整个目录复制过去 |

Codex 从 v0.117.0 起改用 Agent Skills 约定（按当前目录 → 各级父目录 → 仓库根 → `~/.agents/skills/` → `/etc/codex/skills/` 的顺序扫描），**所以 `.agents/skills/` 这一份它直接认**。
Claude Code 认 `.claude/skills/`（旧写法 `.claude/commands/xxx.md` 也仍然有效，两者都会生成 `/xxx` 命令）。

**唯一要动的是 frontmatter**。本仓库的 `SKILL.md` 用了两个 DSH 扩展键：

| 键 | 怎么办 |
|---|---|
| `whenToUse` | 别的运行时不认。**把它的内容并进 `description`**——`description` 本来就是这件事的触发器 |
| `user-invocable` | Claude Code 认这个键（语义相同，可留）；Codex 不认，删掉即可 |

Claude Code 版保留 `name` + `description` 就能跑。想更贴它的习惯，还可以加：

```yaml
context: fork                          # 让这个 skill 在隔离子代理里执行——正好对应本协议的"出片派子代理"
agent: moyu-writer                     # 需要在 .claude/agents/moyu-writer.md 里定义这个子代理
allowed-tools: Read, Write, Edit, Bash(node *)
```

Codex 版可选加一个 `agents/openai.yaml`（放在 skill 目录里），让 `/` 菜单显示中文名并预填提示：

```yaml
interface:
  display_name: "墨月写卡"
  short_description: "用对话做一张 SillyTavern 角色卡"
  default_prompt: "用墨月帮我做一张角色卡"
policy:
  allow_implicit_invocation: true
```

### 12.2 子代理派发（真正要动手的一处）

本协议第四节是给 DSH 的 `subagent` 工具写的：起一个**通用子代理**，让它读请求文件、把成品写到稿件路径、只回一行。换运行时的对应做法：

| 运行时 | 怎么做 |
|---|---|
| DSH | `subagent` 工具 + 第四节那段派发模板（现状） |
| Claude Code | frontmatter 里 `context: fork` + `agent: <名字>`；或在正文里让主代理用 Task 工具起子代理，沿用同一段模板 |
| Codex | 没有独立子代理：退化成主代理直接执行，或拆成两轮（第一条消息装配并落盘，第二条消息读文件产出） |

**不管换到哪个运行时，这四条约定不要改**（这是上下文不被打爆的关键）：

> 请求落盘 → 执行者读文件 → 成品落盘 → 只回一行

别把 10–20KB 的装配结果和整份成品倒进主对话。

### 12.3 命令行写法（跨平台）

- **路径分隔符**：`墨月_harness\工具\check.mjs` → `墨月_harness/工具/check.mjs`（macOS / Linux）。
- 协议里**唯一一处绑平台的写法**是 PowerShell 的 `"$env:TEMP\检查.json"`。换成普通相对路径就跨平台了：

  ```
  node "墨月_harness/工具/check.mjs" <专项> --file "<稿件>" --project "<作品.json>" \
       --json --out "墨月_harness/状态/请求/检查.json"
  ```

- 「每次调用都是新进程，所以必须写全路径」这条与运行时无关，继续照做。

### 12.4 移植后必查三条

1. **工具本身没坏**：`node 墨月_harness/工具/check.mjs --self-test`（其余七套同理，共 165 项）必须全绿。这一步只验工具，与 agent 无关。
2. **循环没走样**：让那个 agent 用自己的话复述它每一轮做什么，必须包含「**装配 → 执行 → 校验 → 问作者 → 写入**」五步。缺任何一步，就是移植出了问题。
3. **闸门真的会拦**：故意塞一份不合格成品（比如世界书配置漏掉激活策略），看它是否被 `check` 拦下、进维修轮重出。**这是移植时最容易被"好心"绕过去的一环**——别让它用"内容其实是对的"把闸门跳过去。

### 12.5 一句忠告

如果有人想把这套东西"简化"成"让模型自己按提示词检查一下"——那就不是这套东西了。这里的价值恰恰在于：**检查是程序做的，不是模型自称的。**
把 `墨月_harness\工具\` 整个丢掉、只留知识库和提示词，做出来的是另一个东西（未必更差，但别叫它墨月）。
