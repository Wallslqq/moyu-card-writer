# 批处理层 · 整组任务

> 等价物：`moyu_prepare_batch` + `batch-artifact.ts` + system 的 `<agent_batch_delivery>` 段。
> 运行载体：**workflow**（`pipeline()` 逐项生成 → 逐项校验 → 整组验收 → 整组确认）。

---

## 一、触发条件（三条全中）

1. 通路是 **Agent**（普通问答不出片）
2. **不是**自查轮
3. 域 ∈ {`worldbook`, `mvu`}

**这条补充不是默认扩大工作范围。** 单条任务仍走交互层；普通问答与成品自查**永不**走批量。

---

## 二、容量与分组

| 域 | 条数 | 单条上限 | 整批上限 |
|---|---|---|---|
| 世界书 | 2–8 条 | 4000 字符 | 16000 字符 |
| MVU | 2–3 份文件 | — | 16000 字符 |

MVU 只允许这三种文件：
`mvu_schema_compilation`（schema.js）、`mvu_initvar_formatting`（initvar.yaml）、`mvu_update_rule_formatting`（变量更新规则.yaml）。
**不含状态栏与前端。**

约束：

- 同一目标不能在一批中重复提交；
- 世界书每项必须**恰好一个**正文与配对配置块，混入多条即拒绝（"请分别列入 items"）；
- **条目数量不是世界观规模**：作者要求一次处理数条短条目，**不得**因此重问世界观规模，也不得擅自合并；
- 超出容量时**说明具体要分成哪几组**，逐组完成。**不得截断、不得用占位符、不得删必要规则或削弱结构来通过限制。**

---

## 三、世界书批量

- **修改已有条目**：必须提供目录中的准确 `targetId`（不得用名称代替）。只提交该条**完整正文**；名称与发送设置**保留原值**，不必重复配置。
- **新增条目**：省略 `targetId`，提供正文 + 配对配置。
- 各条按职责分别选 `worldview_small / medium / large` —— **不把单个小型世界观擅自拆大**。
- 写入时**只改正文**；名称、发送设置、未知扩展一律沿用确认时的原对象。

## 四、MVU 批量

覆盖交互层的两条限制（这是批量的**唯一**特权）：

| 交互层规则 | 批量时改为 |
|---|---|
| 本轮只生成一份文件 | 本批逐份生成、整组确认 |
| 上游须已保存 | 同批上游草稿就是下游依据，**无须先写入再换页** |

**不变的技术要求**：Zod 4、YAML 结构、`_` 前缀只读字段、路径规则（initvar 无 `stat_data` 外壳 / 规则无 `stat_data` 且无 JSON Pointer / 状态栏必须带 `stat_data.`）。

未提交的文件沿用已保存内容；无需改变的文件不重写。整组必须能互相对应（整组过三文件交叉检查）。

---

## 五、执行流程（workflow 映射）

```
输入：域 + 待生成项清单（含 targetId 与每个目标的 base 快照）
  ↓
[逐项] agent 生成（pipeline，无 barrier）
  ↓
[逐项] check <taskId> <content>        ← 每项独立校验
  ↓
[整组] 整组校验
        · 世界书：条数/容量/单项唯一性
        · MVU：checkMvuFiles 三份一一对应
  ↓
[整组] 通过 → 建立一份待确认稿（含 base 快照）
        失败 → 只报出错的项 + 四段式处方，**整组不建立**
  ↓
作者确认 → pack --apply → 整批写入
```

**任何一项校验失败**：修正错误后**重新提交完整一组**；已经正确的内容保持原样。

**准备成功即结束本轮**：不逐条调用单份工具，也不在准备成功后再调用一次（防覆盖）。

---

## 六、确认写入的整组纪律

1. **整批一起过**：任何一项失败则整批不写，绝不写一半。
2. **base 校验**：逐项比对生成时的快照与当前内容——
   - 世界书：`title + content`；
   - MVU：三份文件的完整内容。
   不一致 → `「X」在生成后被修改或删除，请按最新内容重新整理；整批尚未写入。`
3. **不重复确认**：已确认过的批次再次 confirm 直接拒绝。
4. **保留身份**：世界书批量写入时，已有条目按 id 原地更新，新增条目 append；未涉及的对象身份与内容不动。
5. 写入后回读 + 记录操作日志 + 更新 `updatedAt`。

---

## 七、与交互层的边界

| | 交互层 | 批处理层 |
|---|---|---|
| 载体 | skill + 子代理 | workflow（`pipeline`） |
| 每次范围 | **一个**工件 | 2–8 条 / 2–3 份 |
| 上游依赖 | 必须已保存 | 同批草稿可充当下游依据 |
| 失败处理 | 逐轮维修 | 修正后整组重交 |
| 共同点 | 都要过 `check`；都只写待确认区；都要作者确认；都不得声称已写入或在酒馆运行通过 | 同左 |
