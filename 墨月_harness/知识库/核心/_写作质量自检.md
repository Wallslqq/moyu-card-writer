# 写作质量自检

> **本文件是写作质量检查的共通依据。** 两个地方共用它：
> ①**创作前自检**——主代理在写每一栏／每一条之前，先按本表预演要写的内容；
> ②**落盘后扫描**——模块（位置组）闭合后，由审稿子代理在独立上下文里扫一遍。
>
> **不得把本表的违规范例当作创作素材**，也不得为了规避本表而矫正过度（见文末「例外」）。
> 本表只判**文字质量**。结构、命名、配置是否合规由 `check.mjs` 判定，两者不互相替代。

> ⚠️ **维护须知**：本文件是**手写件**，不在 `import-knowledge.mjs` 的生成范围内
> （生成器只写它 `files` 列表里的文件，重跑不会删它）。
> 但知识库其它 `*.md` 是**生成物**——**要改那些必须改 `_源_prompt-bundle.json`**。

---

## 一、这份标准从哪里来

本表不是外来规矩，是把墨月知识库里**已有的写作标准**汇成一份可执行的检查表。
以下每一条都能追溯到原知识条目；冲突时以知识库正文为准。

| 来源 | 提供了什么 |
|---|---|
| `人物/airp_character_nature.md` §七「反迎合与质量判断」 | 七条「模型倾向风险」+ 禁止空泛评价 |
| `人物/npc_light_habitat.md` | 外貌／穿衣／关系只写有作用的；性情不写成常驻状态 |
| `开场白/opening_style_then_draft.md` | 开场六项收敛；文风不得堆空泛目标 |
| `人物/airp_clothing_style.md` | 禁止把具体套装写成清单 |
| `世界/worldview_small.md` | 世界观压缩：只写会改变理解与行动的内容 |

## 二、创作前自检（第一道防线）

**时机**：写每一栏／每一条**之前**，主代理在内部预演。
**力度分档**：

| 场景 | 自检范围 |
|---|---|
| 自动生成（agent 起草） | 逐项过本表全部小节 |
| 作者手写、agent 只整理 | 只查 agent 自己补的部分，不动作者原文 |
| 修改已有内容 | 增量自检：只查本次改动部分 |

**主代理不得跳过这一步。** 命中任一项即调整思路，不要等落到文字再返工。

---

## 三、落盘后扫描（第二道防线）

**时机**：一个模块（或一个位置组）的条目全部落盘后。
**执行者**：审稿子代理（独立上下文）。
**范围**：整组一起送检，这样还能查出**条目之间**的重复与标签化。

### 收敛判据（防止无限返工）

审稿子代理**来回不收敛**是实测踩过的坑（13→9→6→6 条，且第三轮起开始要求编造人物事实）。
所以修正闭环有明确终点：

1. **只改报告点名的问题**，不得顺手改别处。
2. **改写不得引入同类新问题**。
3. **收敛判据**：连续两轮扫描都没有**新的违规项**（同一项反复报同样的问题不算新），即视为通过。
   —— 允许存在少量"疑似"项由作者裁决，**不要求清空全部提示**。
4. **最多三轮**。三轮仍未收敛 → 停下来把分歧交给作者，**不要自己继续改**。

### 绝对边界：审稿子代理不得要求新增事实

**这是硬边界。** 审稿子代理只做**减法与改写**：

- ✅ 可以要求：删冗余、改语序、把抽象标签换成行为、去掉重复与引用、补场景锚点。
- ❌ **不可以要求**：给人物补一段经历、给关系补细节、给配角补父母职业、发明任何作者没写过的事实。
  这类要求违反 `airp_intake_router` 的「不得替用户补写内容」。

如果某处确实"缺信息"，审稿报告只能写「此处信息不足，**需作者补充**」，
**不能自己编一个版本要求作者接受**。

## 四、检查项

### 4.1 抽象与标签（最高频问题）

抽象词没有作者含义时，模型会回到公共模板。

| 模式 | 违规 | 合规 |
|---|---|---|
| 抽象标签 | 「性格温柔善良」 | 「遇到受伤的小动物会带回家」 |
| 空泛评价 | 「很鲜活、很真实、很有张力」 | 指出可检查的跨场景作用或具体风险 |
| 抽象性情词无定义 | 只写「冷静」 | 写清这个人在她身上**具体指什么** |
| 空洞关系 | 「感情深厚」 | 「每次见面都会先抱一下」 |

**判定**：这个词在这个人物身上具体指什么？答不出，就是没有作者含义。

### 4.2 固定化与复读风险

具体动作或台词过醒目，模型会反复照搬。

| 模式 | 违规 | 处理 |
|---|---|---|
| 固定动作菜单 | 「每次都推眼镜、冷笑」 | 删，或降为倾向而非固定反应 |
| 固定台词库 | 列一串口头禅 | 删，留给场景生成 |
| 情绪触发表 | 「被提到家人就会沉默」 | 只有作者明确要求才保留 |
| 场景结局预写 | 把某个场景的结果写死 | 删，结局由剧情生成 |
| 具体套装清单 | 列出上装下装鞋配饰 | 改为「选择倾向」而非库存 |

**判定**：这段会不会让模型在每轮都照抄同一个动作？会则改。

### 4.3 心理与视角（远距离叙事）

角色应通过言行呈现，不是被远距离描述的客体。

| 模式 | 违规 | 合规 |
|---|---|---|
| 情绪宣告 | 「她感到一阵悲伤」 | 「她别过脸去」 |
| 过度心理独白 | 大段自我分析 | 保留关键 1–2 句 |
| 假性主体 | 「一个念头在她心里成形」 | 「她想到……」 |
| 被动承受 | 「她被复杂的情绪包裹」 | 改为具体行为 |
| 自我认知宣告 | 「她意识到自己错了」 | 「她放下杯子，说『是我的问题』」 |
| 上帝视角预告 | 「她不知道这个决定将改变一切」 | 删 |

**判定**：问「她做了什么／说了什么」，而不是「她感到了什么」。

### 4.4 关系不能吞没人

与使用者的关系占满全部性情时，人物在对方不在场时会失去行动原因。

- 人物离开对方视线后，是否仍保有一件自己的生活、责任或目的？
- 是否默认人物喜欢、照顾、敌视或特别关注使用者？

### 4.5 强行立体

为追求立体强行增加反差、创伤、隐藏人格，人物会像几套人格切换。

- 是否在创造作者没提过的创伤、核心矛盾或隐藏身份？
- 两项性情无法同时成立且未说明条件时，是否隐瞒了冲突？

**复杂度可以来自多个方向在具体处境中的牵动，不需要制造反差。** 没有真实牵动时，简单直接同样成立。

### 4.6 重复与挤压

- 同一个意义在多段中重复，会挤压其他信息。
- 跨栏目重复：同一事实／行为锚点／人设特征在多处出现？
- **判定**：抽掉任一处，其信息是否已被另一处覆盖？是则删重复的那处。
- 一个细节被反复使用（同一个比喻、同一个动作锚点）也是重复。

### 4.7 独立可读

每条必须独立可读，不依赖其他条目。

| 模式 | 违规 | 处理 |
|---|---|---|
| 详见引用 | 「详见老张身份」 | 把关键句写进来 |
| 配套说明 | 「与世界观 X 配套」 | 删 |
| 跨阶段引用 | 「比第一阶段更克制」 | 删（条件块之间互不可见） |

**判定**：删掉条目名与触发词后，只看正文是否仍成立？

### 4.8 世界观压缩

世界观不是百科全书。**每句话过四问**：

1. 它会改变理解吗？
2. 它会改变选择吗？
3. 它会改变行动的代价或后果吗？
4. 删掉它，实际游玩会缺什么吗？

四问皆否 → 删。骨架不得展开地区内部建筑、势力成员、完整历史或地方习俗。

### 4.9 开场白专项

开场必须把互动交到使用者手里。检查六项是否落地：

- [ ] 故事从哪个**具体时刻**开始
- [ ] 当前地点提供哪些**真实行动可能**
- [ ] 哪些人物在场、各自在做什么
- [ ] 此刻有什么已经发生、正在改变、或即将要求反应
- [ ] 在场人物各自**能知道什么**，哪些信息尚不可见
- [ ] 在哪里把互动交给使用者

**空场景是常见违规**：「天气很好，你走在街上」→ 缺具体时刻、缺物件、缺可进入的行动。

### 4.10 表达与语序

| 模式 | 违规 | 合规 |
|---|---|---|
| 翻译腔系表句 | 「她是拘谨的」 | 「她表现得拘谨」 |
| 介词前置 | 「对这件事，她始终是回避的」 | 「她一直回避这件事」 |
| 被动式 | 「一股温暖被她感受到了」 | 「她心里暖洋洋的」 |
| 冗余破折号 | 「她会照着做——从小习惯了」 | 「她会照着做」 |
| 空泛文风目标 | 把「细腻、沉浸、自然」堆成文风 | 说明它们**具体改变什么** |

**破折号判定**：删掉破折号及后半段，前半段是否仍完整？完整则破折号冗余，删。

### 4.11 元叙事

删掉写给作者看的笔记，只保留给模型看的内容。

| 模式 | 处理 |
|---|---|
| 写作指引「AI 写作要点：……」 | 删 |
| 用途说明「戏剧用途：承担反差」 | 删 |
| 标记词「本卡独家」 | 删 |
| 整理过程、检查说明、完成度评价 | 删 |

**判定**：这段是给作者看的笔记，还是给模型看的内容？

## 五、例外（防止矫正过度）

- 正常使用「笑了」「皱眉」「攥拳」等常见动作词**不算**违规。
- 白描是简洁直接，不是物理学描述。「目光停留 1.5 秒」这类空洞数字才违规。
- 作者明确要求的固定反应、口头禅、硬规则**不算**违规——那是作者的选择。
  这一类只在「作者没要求、但文字会诱导模型复读」时提示风险，不擅自删改。

## 六、输出格式（审稿子代理用）

```
检查结果：通过 / 不通过

不通过时逐条列出：
- [文件 / 行号] 违规类型：具体问题描述
  原文：「……」
  建议改为：「……」
```

**只放位置、类型、原文、建议。** 不放「大致没问题」「整体还行」「这段不错但小处可改」。
**大致没问题就是有问题。** 但也不得为了显得严格而把例外项报成违规。
