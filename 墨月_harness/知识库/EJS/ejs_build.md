# EJS 世界书工件正式创作

## 一、运行环境

目标是 SillyTavern 中的 ST-Prompt-Template 世界书 EJS，不是 Node.js 文件，也不是浏览器页面脚本。可使用标准 EJS 控制标签和扩展在当前版本公开提供的 API；只能调用合同明确要求且知识中能够确认的能力。

当前合同若读取 MVU，逐项调用 `getvar('stat_data.完整路径')`；第二参数 `{ defaults: 缺省值 }` 可选，仅在已确认的缺失处理需要默认值时提供。函数名大小写敏感且必须是全小写 `getvar`。禁止使用 `getVar`，禁止读取或解析名为 `mvu` 的整段字符串，禁止用 `getMvuData`、`getVariables` 或其他自行猜测的函数代替。每条路径必须逐字来自当前 MVU 文件。

常见结构：

- `<% ... %>`：执行控制代码，不直接输出。
- `<%= ... %>`：转义输出表达式结果。
- `<%- ... %>`：按 EJS 语义原样输出表达式结果，只有合同需要时使用。
- `<%# ... %>`：EJS 注释。复杂工件需要分段闭合时可以使用 `@qk-unit` 控制注释，网页会在写入前清理；它不是有效工件的必需标记。
- 条件、循环和局部变量必须在同一份工件内闭合。

扩展可能提供变量、角色卡、世界书、消息或注入相关 API。具体函数名与参数必须来自当前知识或作者提供的正式资料；不因“听起来合理”自行发明。作者没有要求副作用时，使用只读处理。

## 二、正式工件要求

1. EJS 从第一行到最后一行完整输出，不能用省略号、补丁或“其余不变”。
2. 所有 `<%` 与 `%>` 数量一致，JavaScript 控制结构闭合。
3. 所有变量路径、条件、文本与 API 调用逐项对应已确认合同。
4. 不命中条件时按合同回退；合同没有输出时必须真正保持空输出，不能泄漏阶段名、调试说明或技术错误。
5. 按已确认的约定处理缺失数据；默认值、空输出与进入未命中分支是不同语义。修复现有成品时保留其缺失处理，只有该处理被证实有错才调整；`0`、`false` 或空数组不属于缺失。
   合同约定读取失败回退时，用局部异常处理包住实际读取，并继续输出约定的回退正文。
6. 若输出内容本身包含 XML／提示词标签，标签也必须完整闭合。
7. 只在合同明确需要时产生写回、注入或其他副作用；副作用必须防止每次渲染重复执行。
8. 最终源码必须自行闭合；完成与否由 EJS 标签、JavaScript 控制结构和合同内容检查，不使用自报完成注释代替检查。

## 三、小 COT 流式闭合

复杂工件不要先写一大段计划。按实际结构边生成边闭合：

```ejs
<%# @qk-unit | 单元=输入读取 | 依据=方案中的读取内容 | 边界=不执行输出 | 完成=所有输入取得安全值 %>
<% /* 完整输入读取代码 */ %>

<%# @qk-unit | 单元=条件与输出 | 依据=方案中的条件和正文 | 边界=不扩展新功能 | 完成=分支与默认路径闭合 %>
<% /* 完整控制结构 */ %>
最终需要发送给模型的内容
<% /* 完整闭合 */ %>

```

注释之后紧跟其负责的成品代码。控制注释不是对作者的解释，不得改变工件执行结果。

