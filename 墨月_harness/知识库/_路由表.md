# 专项路由表（可执行规格）

> 等价物：墨月 `page-assistant.ts` 的 `resolvePageTask()` + `resolveConversationTask()`，
> 以及 `AssistantPanel.submitMessage()` 里 `artifactIntent` 的汇总条件。
>
> **本表是确定性的：输入固定 → 输出唯一。** 每条域内规则**按顺序求值，第一条命中即停**。

---

## 一、输入四元组

| 输入 | 取值 | 说明 |
|---|---|---|
| `domain` | `overview` `carddata` `character` `worldbook` `rules` `opening` `mvu` `statusbar` `frontend` `ejs` `package` | 当前制卡域（等价于墨月的"页面"） |
| `focus.targetId` | 对象 id 或空 | 当前选中的条目/人物/工件 |
| `focus.area` | 栏目名或空 | 当前选中的子区域（页签） |
| `intent` | `answer` / `artifact` / `self-check` | 本轮交付意图（**显式优先**；未显式时按 §五 从输入推断） |
| `project` | 作品状态 | 判定上游是否已保存（MVU 用）、路线（状态栏用）、是否已有人物（人物用） |

**`intent` 的来源**：harness 里由作者显式声明（等价于墨月的三个按钮）；若未声明，按 §五 的正则回退推断。**显式声明永远压过推断。**

## 二、通用前置：`artifactIntent` 汇总

墨月的成品权限不是单纯由任务决定，而是三条条件与出来的：

```
artifactIntent = (self-check 或 requestedArtifactIntent)
                且 (存在 batchScope 或 task ∉ {mvu_cross_check, worldview_scale_router})
                且 domain ∉ {overview, package}
```

其中 `batchScope = agent 通路 且 非自查 且 domain ∈ {worldbook, mvu}`。

**⚠ 一处必须照实说明的语义（源码核对结论，2026-09-14）**：
`Boolean(batchScope) ||` 这一项把后面那条禁项**旁路掉了**——因为 `mvu_cross_check` 只出现在 mvu 域、`worldview_scale_router` 只出现在 worldbook 域，而这两个域在 agent 轮里 `batchScope` 恒为真。所以：

- **实际生效的只有 `domain ∉ {overview, package}`**（这一条是硬拦）；
- `mvu_cross_check` 与 `worldview_scale_router` 在墨月里**具备出片权限**，真正的约束来自它们的**专项合同**（"交叉检查只报告不产第四份文件"、"规模判断只给结论后停止"），而不是闸门。

本 harness **忠实复刻**该行为（`工具/lib/route.mjs` 的 `resolveDelivery()` 逐字同式），
并在自测里用一条用例把这条 quirk 固定下来，避免以后被"顺手修好"而偏离原实现。
若将来要收紧，应作为**有意的加固**单独立项，而不是混在复刻里悄悄改。

由此得到的硬结论：

1. **`overview` 与 `package` 域永不能出成品。**（作品设置与检查导出没有"待确认稿"概念；它们仍会路由到自由创作助手取得知识与方法）
2. `mvu_cross_check` / `worldview_scale_router` 的出片约束靠**合同与知识**，不靠闸门。
3. **`self-check` 只用于已保存的代码成品**：`mvu`（initvarSource / updateRulesSource / schemaSource）、`statusbar.source`、`frontend.source|previewHtml`、`ejs.source`。文档类成品（人物/世界书/规则/开场白）**没有自查通路**。

## 四、会话承接规则

路由出结果后，还要过一层"是否允许换专项"：

1. **规模结论承接**（唯一允许从上一轮回答改变任务的情形）：
   仅当 `domain==worldbook` 且 锁定专项是 `worldview_scale_router`，
   且上一轮回答里出现形如 `世界观规模：小型|中型|大型` 的独立行（去掉 `**` 后匹配）→ 用该档覆盖。
   **不从正文地名、题材或字数推测规模。**
2. **规模分流的特例**：若此时路由结果不再是 `worldview_scale_router` → **直接换任务**（不受下面的锁定约束）。
3. **状态栏规划特例**：`domain==statusbar` 且路由到 `mvu_statusbar_briefing` 且（规划焦点 或 改需求）→ 允许换任务。
4. **锁定既有会话**（普通问答且该会话已有消息或记忆）：
   - 任务 = 锁定专项（不换）；
   - 若路由建议不同 → 输出 `suggestedTask` **提示作者**，不擅自切。
5. 其余情况：任务 = 路由结果 ?? 锁定专项。

## 五、意图推断（仅在作者未显式声明时使用）

`requestsArtifact(input)` 的等价实现，顺序：

1. **按分句剔除否定**：以 `，。！？；,!?;\n` 切分，丢弃匹配
   `(?:不要|别|不用|不必|无需|暂不|先不|不需要).{0,12}(?:生成|输出|制作|写入|写回|写代码|成品|工件)` 的分句。
2. **疑问句开头排除**：`^(?:为什么|为何|怎么(?:还|又|会|不能|无法)|哪里|哪儿).{0,24}(?:生成|写入|写回|输出|制作|成品)` → **不是**成品请求。
3. 命中任一即视为成品请求：
   - `(?:请|麻烦|帮我|给我|替我|我要|我需要|现在|直接|开始|继续|重新).{0,24}(?:写入|写回|准备写入|写一份|写出来|写好|生成|输出|制作|整理成|整理为|改成|编译|完成这部分|建立待确认|准备工件)`
   - `把.+(?:写入|写回|整理成|整理为|改成|制作成|生成为|输出为)`
   - `按.+(?:生成|制作|写入|写回|整理成|整理为|编译)`
   - `(?:建立|准备|放入).{0,10}(?:待确认|工件|成品)`
   - `^(?:重新)?(?:写入|写回|准备写入|写一份|生成|输出|制作|整理成|整理为|编译|完成这部分)`

> 墨月自己的注释：这只是"常见中文指令"的识别，**不替代完整语义理解**；实际写入仍须作者确认。harness 里应优先让作者显式声明意图，此节仅作兜底。

## 六、与墨月的实现差异（等价性说明）

| 项 | 墨月 | Harness | 是否等价 |
|---|---|---|---|
| 路由机制 | 浏览器端正则匹配输入 | 同一套规则；`intent` 改为显式优先 | ✅ 结果等价，输入更可靠 |
| 会话状态 | Vue 响应式 project + activeThreadIds | `状态/作品.json` + 会话文件 | ✅ |
| 焦点 | UI 选中态 | `focus.targetId` / `focus.area` 显式字段 | ✅ |
| 批量触发 | `batchSection()`：agent 且非自查 且域 ∈ {worldbook, mvu} | 同 | ✅ |
| 知识注入 | `prepareMoyuPrompt()` 拼 system | 按本表选文件 + 同一套注入顺序 | ✅ 见 `流程/交互层.md` |
